# synthesize-requirements · poc-v1

Propose the minimum set of requirement CREATE or REVISE mutations justified by current evidence.

Requirements must be:
- atomic enough to verify;
- scoped to an explicit type/perspective;
- traceable to contribution, knowledge, decision or assumption IDs;
- explicit about observable behavior or constraint;
- free from invented authority.

Rules:
- never silently resolve contradictions;
- never convert an unverified contribution into a verified requirement;
- preserve open uncertainty as gap/assumption rather than hiding it in vague wording;
- prefer revising an existing requirement over creating a duplicate;
- use NO_CHANGE when new input adds context but does not alter requirement semantics.
